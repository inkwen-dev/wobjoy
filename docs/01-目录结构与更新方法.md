# 目录结构与更新方法

本目录用于维护 Wobjoy 的公开游戏介绍，不保存游戏实现。英文和中文按相同游戏标识组织；首页、游戏介绍和图片引用通过同一个数据文件生成，减少重复维护。

## 一、文件职责

| 文件 | 职责 |
| --- | --- |
| catalog.json | 唯一维护本站地址、游戏标识、试玩路径、封面路径及中英文介绍 |
| build_catalog.py | 将数据渲染为两种语言的首页和单游戏介绍；不访问网络、不发布 |
| README.md、README.zh-CN.md | 面向玩家的目录，由脚本生成 |
| games/en、games/zh-CN | 按同一游戏标识生成的介绍页 |
| assets/brand/wordmark.svg | 从主站公开品牌素材复制的字标 |

## 二、内容与图片维护

1. 玩法、名称和网址先核对主站开发仓库 `inkwengame-h5` 的游戏目录、对应游戏翻译与操作实现。这里保存经过核实的介绍快照，不自动解析 TypeScript，不宣称已实现跨仓同步。
2. 在 catalog.json 同时填写 en 与 zh-CN。游戏标识不随翻译改变，试玩路径与图片路径分别保存，不能根据标识猜测路径，例如 hanoi 的试玩路径是 tower-of-hanoi。
3. 图片直接引用主站 HTTPS 公开地址，不为介绍仓库单独搭 CDN。当前封面随主站更新，删改主站路径前必须检查本目录消费者。品牌字标为本地副本，主站品牌变化时重新复制核对。
4. 执行 `python build_catalog.py`。不要直接修改生成的 Markdown；版式调整只改生成器。
5. 检查两种语言游戏集合、相对链接、试玩页面与图片响应。新增语言时补齐该语言文案及渲染入口，不给全部语言复制维护独立链接清单。

## 三、发布边界

这是介绍仓库，不是游戏源代码仓库；不自动添加代码许可证，不启用 GitHub Pages。同一份本地仓库维护两个远端：GitHub https://github.com/inkwen-dev/wobjoy （origin），GitLab https://gitlab.com/wobjoy-group/Wobjoy-project （gitlab），默认分支均为main。2026年11月23日经本人授权创建并推送，账号与仓库公开状态已在指定的第二个Chrome窗口核对。

建议 About Description：Free browser games on Wobjoy: puzzles and casual challenges, with English and Chinese game guides.

Website：https://wobjoy.com/ 。Topics：browser-games、puzzle-games、casual-games、wobjoy。Description、Website及四个Topics均已在GitHub保存并读取确认。后续修改目录后检查差异、提交并推送至同一仓库；品牌或栏目调整同步检查About字段。

## 四、多语言与双远端同步

catalog.json的languages登记语言标识、名称、首页文件与网站语言路径；每个游戏按语言保存名称、简介、操作说明。当前正文提供英文和简体中文，不代表所有内嵌第三方游戏的菜单都已翻译。新增语言需补齐全部游戏文案和生成器章节文案，不以英文冒充翻译。

当前公开目录含13款正式游戏；开发预览专用条目不自动发布。Gustwing封面由构建生成哈希路径，当前目录先不放图片，避免猜测不存在的固定地址。素材与介绍来源为主站对应catalog-entry及i18n；第三方作品不宣称为本站原创。

更新顺序：修改catalog.json → python build_catalog.py → 检查相对链接和正式网址 → 审阅git diff → 提交 → git push origin main → git push gitlab main。两次推送分别确认；一个成功不等于另一个成功。两平台不各自维护第二份目录。

GitLab原README的官网、双语入口、游戏介绍及AI辅助说明已由公共目录覆盖；首次同步合并双方历史，不强制推送。介绍仓库继续不包含生产源码；若要公开实现，须先明确源码、素材和配置范围。
